# CleanYourMail opt-in feedback implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add opt-in feedback from the CleanYourMail website and Windows app through a dedicated Cloudflare Worker, without telemetry or secrets in either client.

**Architecture:** A `cleanyourmail-feedback` Worker validates a small JSON payload, rate-limits by a salted IP hash in KV, and forwards it to a private Discord webhook that stays in Cloudflare secrets. The static site posts to the Worker from a consented form; the PySide6 app opens a local dialog and sends only after Send.

**Tech Stack:** Cloudflare Workers, Workers KV, Wrangler 4, vanilla HTML/CSS/JS, Python 3.12+, PySide6, pytest, Node `node:test`, Inno Setup.

**Spec:** `docs/superpowers/specs/2026-11-10-feedback-design.md`

## Global Constraints

- App version **0.4.0**; installer `CleanYourMail-Setup-0.4.0.exe`; sidecar stays pinned to **1.2.2**.
- No telemetry, analytics, automatic upload or background network at app startup.
- No secret in argv, QSettings, logs, error dialogs, tests, the website or the app binary.
- The Discord webhook URL and `IP_SALT` are Cloudflare secrets, never committed or printed.
- The checklist may contain: app version, sidecar version, Windows version, provider label, mode, category names, language. It must never contain the account email, config/state paths, subjects, senders, message IDs, passwords, tokens or logs.
- English and Spanish are first-class; every visible app string lives in `i18n/en.json` and `i18n/es.json`.
- Website stays static, no cookies, no third-party assets, no inline script; CSP allows only the Worker origin.
- Worker URL: `https://cleanyourmail-feedback.subtitleme.workers.dev`.
- Website origin: `https://jparedesds.github.io`.
- Discord webhook is a manual Cloudflare secret; the Worker returns 503 until it is set.

## Review Focus

- A person pastes text with Discord mentions or ` ``` ` fences: the Worker must neutralise them and disable mentions.
- A person edits the checklist and leaves an email/path in it: the UI must warn that the text is sent as typed, and the app must never prefill those fields.
- A person double-clicks Send: the form must disable and the Worker must not receive two messages from one click.
- The Worker is called from an unknown origin or with a non-JSON body: it must reject without forwarding.
- The app opens with no connection/settings: the dialog must still open, prefill safe placeholders and not crash.
- The Worker is deployed without the Discord secret: both clients must show a localized "not configured" message, not a generic crash.

- [ ] **Step 4: Create the KV namespace and deploy**
